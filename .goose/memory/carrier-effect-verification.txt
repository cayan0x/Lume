# verification carriers triggers field-data v0.7.4
2026-09-22 现场追踪（最近 12 个会话、逐会话解析 zstd 多帧会话日志）证明 0.7.0 「更聪明」那次大改只生效一半：
✅ 完全生效：分层注入（缓存命中 98%）、方法层（先量化后动手×14 / 改动影响面×14 / 定位工具×16 / 上轮交付复核×13）
⚠️ 半生效：任务契约（3 份真实契约但 expectCount/actualCount 全是 -1）、项目知识（有内容但键是 unknown）
❌ 完全没生效：lume_change 0 次调用（ledger 0 行）、lume_hypothesis 0 次调用、三类触发器从未命中、反思第五维停在 09-20
根因：① 工具型载具依赖模型自觉，而方法块/提醒**没点名工具**；② 数量字段是**可选**结构；③ projectKey 静默回落 "unknown"（不同项目串味）；④ 增量验证判据用**轮内连击**，而连击在 turn/end 清零 → 跨轮改多处永不触发；⑤ EXECUTE_RE 缺「重构/梳理/删掉」→ 重构请求被判成问答，方法层与阶段门控全不生效。
v0.7.4 修法：改动台账**由插件自动记**（mutate 工具一调用就落账，不再依赖模型）；projectKey 空 cwd 返回 null 且不写跨会话表；expectCount 必填 + 渲染始终显示未估/未回填；文案点名 lume_change/lume_project_note；增量验证改为「连击 或 台账未验证项数」；阈值 6→4；假设提醒不再要求已有假设；新增 EXECUTE_EXTRA_RE。
验证教训：**每条改动都要有「驱动真实事件 → 断言存储/注入真的变了」的 apply 层测试**（test/apply-carriers.test.ts），只断言纯函数会出现"代码写了但没接线"。
