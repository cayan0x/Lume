# Lume（微光）

DSH Desktop 增强插件，由两大部分组成：

1. **思考逻辑引擎** —— 决定「怎么把活干对」：P0-P3 四层推理框架，始终注入，与是否使用人设无关
2. **人设系统** —— 决定「用什么口吻说话」：人设是独立的「人」，有自己的名字、自己的记忆，性格会随对话进化，还能纯靠对话创建新的人设

两者互相独立：人设只改自然语言的语气，永远不碰思考逻辑、代码、命令与工具调用的正确性。

## 一、思考逻辑引擎

从 lume 推理引擎提炼的四层思考框架，注入到每个会话的 system prompt。**无论选择哪个人设——包括「不使用人设」——它都在工作。**

### P0 上下文管理

对话历史越来越长时，主动浓缩之前的讨论：保留用户请求了什么、已完成哪些操作、关键决策、遇到的错误、**已排除的假设**——避免上下文耗尽导致的「失忆」与重复劳动。

### P1 阶段门控

分析/计划阶段先用只读工具把现场调研清楚，确认方案之后再进入执行阶段。不带着半懂的计划动手改代码。

### P2 振荡预防

改完代码立即验证，不攒一堆修改再测；同一文件不反复打补丁——先完整读取、理解当前状态，再一次性修改到位；连续失败就换思路，已被排除的假设不再提。专治「改崩—回滚—再改崩」的死循环。

### P3 反思自检

每次操作后自行评估：操作是否成功？结果是否符合预期？失败就分析原因再重试，不盲目重复；每隔几轮主动停下来复盘进度，检查是否偏离目标、有无遗漏步骤。

## 二、人设系统：「人设即人」

### 核心：每个人设是一个独立的人

- 一个会话 = 一系列工作；**切换人设 = 换人接班**。她们底层是同一个大脑（同样的模型、同样的思考逻辑），能力完全一样，不同的只是说话方式 + 各自单独的记忆
- **记忆跟人走，不跟会话走**：在绘画项目里告诉萝莉「你叫小A」，她在任何项目、任何新会话里都记得自己叫小A。记忆以人设为键存放在 DSH 官方 storageDomain（`storages/lume_persona_identity.json`），全部本地
- **性格会进化**：内置的风格契约是基本盘；对话里对她提的语气要求（「少用点 emoji」「自称改成 XX」）会沉淀为该人设的「习得的风格约定」，跨会话生效、与基本盘冲突时以习得层为准
- **接班有仪式感**：切换人设时新人在回复里明确接班（「小B 退场，小A 接手」），并带边界提示压制旧语气的惯性

### 写入通道（双通道）

| 通道 | 机制 | 成本 |
|---|---|---|
| 模型主动写（主通道） | 三个模型可调用工具：`lume_remember`（记住用户的事）、`lume_update_style`(固化风格要求)、`lume_create_persona`（对话访谈创建新人设） | 随正常对话发生，零额外 API 调用 |
| 被动提取（安全网） | 会话轮次结束后，三道门（关键词正则 → 相似去重 → 10 分钟冷却）触发才调小模型提取 | 单次 ~0.003 元，日常对话几乎不触发 |

**对话创建人设**：对当前人设说「我想建一个新的人设」，她会访谈收集设定（名字/性格/说话方式/称呼），然后调用工具保存——新的人设立即出现在下拉里，全程不碰任何配置文件。

### 蒸馏工具：从素材到角色卡

人设菜单底部的「＋ 蒸馏角色卡…」是内容生产的第二条路：粘贴（或导入 .txt/.md）一段小说、剧本或人物设定文档，宿主侧两段式 LLM 管线把它蒸馏成一张与内置卡同构的角色卡——

1. **对话挖掘**（零 token）：抽取引号台词/剧本行、统计说话人、压缩叙述线索；
2. **契约合成**：从语言证据归纳身份/称呼/emoji 规范/语气词/节奏/立场 + 硬性约束 + 发出前自查；
3. **语料合成**：8 条「用户↔角色」示例对话（assistant 侧复刻角色原声）。

预览全部字段可编辑，确认后保存即出现在下拉菜单。素材走 RPC 由宿主后台蒸馏（任务制 + 轮询），不进对话上下文、不打断当前会话；蒸馏路由可用 `distillProvider` / `distillModel` 指定专用档（默认跟随主对话模型）。素材上限 20,000 字；素材视为不可信文本，其中任何指令不会被执行。

### 人设切换

- 切换即时生效（无需重启会话）；输入栏置底时菜单自动向上弹出
- 跨会话记住每个会话的**显式选择**；新会话默认「不使用人设」

## Token 预算与优化算法

| 注入段 | 无优化 | 优化后 | 用的算法 |
|---|---|---|---|
| 思考逻辑 P0-P3 | ~350 | ~350 | 不动（基本盘） |
| 人设契约 | ~350 | ~250 | 契约电报化 |
| 语料示例 | 6 条 ~600 | 稳态 2 条 ~200 | 少样本衰减 `max(2, 6−轮数)` |
| 工具定义 ×3 | ~600 | ~450 | description 紧凑化 |
| 记忆 | 15 条 ~350 | core+top5 ~120 | 相关性检索（本地分词，零成本） |
| 风格层 | 10 条 ~250 | top5 ~120 | 同上 |
| 身份 | ~80 | ~80 | 恒注入 |

- **成熟态稳态：~1,570 tok/请求（比无优化省 39%）**；缓存友好分层（静态前/易变后）叠加 DeepSeek 前缀缓存后，有效计价再降约一个数量级
- 对比 v0.2.0（~1,400 tok）：v0.3.0 全部新功能的稳态净增仅 **~170 tok/请求**
- 旋钮：`sampleCount` / `sampleMin` / `memoryInject` / `styleInject` / `injectionStrategy: "topk" | "full"` 均可配置
- 提取旋钮：`extractionEnabled` / `extractionCooldownMs`；提取默认跟随主对话模型，可用 `extractionProvider` / `extractionModel` 指定更便宜的专用档（可只配其一，另一维回落主对话）

## 存储

- 会话选择：`storages/lume_persona_state.json`（真 LRU，200 会话上限）
- 身份/记忆/风格/自定义人设：`storages/lume_persona_identity.json`（记忆 cap 30、风格 cap 20）
- v0.1.0 旧 `persona-state.json` 首次启动自动导入改名 `.migrated`；全部数据本地，不上传任何远端

## 安装

```bash
dsh plugin add github:cayan0x/Lume            # 最新版本
dsh plugin add github:cayan0x/Lume#v0.3.0     # 指定版本
```

## 开发

```bash
npm install --legacy-peer-deps   # DSH 生态包在公共 npm 可装
npm test                         # vitest：单测 + 真实存储栈集成测试
npm run build                    # tsc（宿主 lib/index.js）+ tsdown（客户端 lib/client.js）
npm run watch                    # 客户端 bundle 增量构建
```

结构：

```
src/index.ts            宿主入口：注入 + RPC + 工具 + 事件接线
src/core/               纯逻辑：种子采样、检索打分、衰减、manifest 解析、文本组装
src/host/               存储（选择/身份）、提取器、工具、RPC、注册表
src/client/index.tsx    前端：官方 Menu 原语的人设下拉（插槽 conversation.input.left）
lib/                    构建产物（index.js / client.js）
test/                   vitest 单测 + storage 栈集成测试
```
